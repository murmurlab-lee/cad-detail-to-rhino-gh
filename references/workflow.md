# 工作流参考：节点详图 PDF + 照片 → .3dm + .ghx

## 阶段总览

```
1 读图解析 → 2 疑问清单(用户确认门) → 3 参数体系设计 → 4 Python 建模(.3dm)
→ 5 几何校验+预览 → 6 .ghx 生成+编译验证 → 7 交付(恰好三件) → 8 自动入库 → 9 排障回路
```

## 阶段 1：读图解析

1. `scripts/pdf_to_png.py 图纸.pdf -o work/ [--dpi 150]`（矢量 CAD PDF 直接读文本是空的，
   必须栅格化；标注看不清就提到 200-300 dpi 或裁切局部放大）。
2. 逐区读图：定位**平面图 + 剖面图**，抄录**三类图面信息**：①尺寸标注；
   ②**构造注记**（孔、槽、坡、预埋件、焊接/螺栓、表面处理、材料文字说明——
   逐条编号，一条不许漏）；③标高关系。
3. 照片用于佐证"完成面可见什么"（哪些构造是埋藏的、材质质感、构造关系）。
   **数值优先级铁律：一切数值以图纸标注为准，照片只用于判断构造关系/可见性/
   材质，不得用于推翻图纸数值。** 照片观感与图纸冲突时（如缝宽），默认值仍取
   图纸值，观感差异写进 .ghx description 的假设清单。
4. **标注矛盾是常态**（如平面写 2mm、剖面写 10mm）→ 记录矛盾点，列入疑问清单，
   不要自行二选一。

## 阶段 2：疑问清单（默认强制确认门）

除非用户明确说"全自动、不用问我"，否则必须先输出疑问清单并等用户回答。只问
**关键尺寸与构造逻辑**，一次问完：

- 净空/外形控制尺寸（图纸缺失或矛盾的）
- 埋深/高度方向的控制尺寸
- 标注矛盾点的裁定（给选项，推荐项附理由）
- 建模范围（仅本体？含井圈/基层？含周边交接？）

细枝末节（缝宽观感、垫块数量等）不问，直接合理假设并写进 .ghx description 的假设清单。

## 阶段 3：参数体系设计

- **变体检查**：此类构件现实中是否存在系列规格/形态变体（圆/方井口、单/双篦、
  不同荷载等级）？若存在且实现成本低，参数体系应覆盖——用形态切换参数（0/1）或
  双尺寸参数（W/L，正方形时 L=W）实现；覆盖成本高则列入疑问清单让用户裁定，
  不要默认只建当前这张图的形态。
- 滑块选"用户后续最可能调的"：控制尺寸、缝隙、厚度类、网格密度类。一般 8-15 个。
- 每个滑块给 min/max/默认值/小数位；默认值为图纸值。
- **同一套坐标推导公式**在 Python（建模）和 C#（脚本体）各实现一遍，变量名保持一致，
  先写 Python 跑通，再翻译成 C# 5 纯方法体（用生成器展开辅助函数）。
- z=0 建议取完成面，向下为负。

## 阶段 4：Python 建模（.3dm）

- 用 `scripts/rhino3dm_helpers.py`：`new_file(图层表)` → `box()`/`ring()` 组合构件 →
  `add_to_layer()` → `write_dual()` 写出（R8 + R7 双版本，**交付只取 `xxx_Rhino7.3dm`**，
  R8 版留在工作目录备用）。
- 构件级精度：盒体组合为主；环形构件拆 4 块。
- 图层按材料/构件分组并配色（低饱和度色系）。

## 阶段 5：几何校验 + 预览

- `scripts/check_intersections.py`：两两相交检查。**先列白名单**（有意的嵌埋/交叉关系，
  如钢网埋砂浆、肋交叉、开孔槽穿过铺装），其余相交必须清零。
- matplotlib `Poly3DCollection` 渲预览图。内部自查可多渲几张（爆炸/底部/剖面对照），
  **交付只给一张轴测图** `xxx_轴测.png`。

## 阶段 6：.ghx 生成 + 验证

1. 写 `body.cs`（纯 RunScript 方法体！铁律见 `references/ghx-format.md` 第 2 节）。
2. 写 `spec.json`（结构见 `scripts/ghx_gen.py` docstring；参考 `assets/ghx_spec_example.json`）。
3. `python3 scripts/ghx_gen.py spec.json -o 输出.ghx --sliders-only 排障版.ghx`
4. `python3 scripts/validate_ghx.py 输出.ghx` — 必须全绿。
5. `python3 scripts/compile_check/wrap_build.py spec.json` — 必须编译通过；
   同时用 `--emit 完整源码.cs` 生成手动粘贴退路文件。

## 阶段 7：交付清单（恰好三件，只输出这三个文件）

1. `xxx_Rhino7.3dm`（文件名显式带版本号；`write_dual` 产出的 R8 版留工作目录备用，不交付）
2. `xxx_参数化.ghx`
3. `xxx_轴测.png`（一张轴测预览图）

配套规则：

- **假设清单 + 图面构造注记对照表**（阶段 1 编号的所有注记逐条"已实现 / 有意省略
  +理由"，以及全部假设）写进 spec.json 的 `description` 字段，随 .ghx 交付——
  不再单独交付建模说明.md。
- 排障版_仅滑块.ghx、完整源码.cs、建模说明.md、其余角度预览图均为**内部文件**，
  留在工作目录；仅当用户反馈报错进入阶段 8 排障回路时按需给出。
- REF 标签只挂这三个交付文件。
- 告知用户：.ghx 在 Grasshopper 直接打开，另存即得 .gh；假设与注记对照见 GH 文档
  属性里的 Description。

## 阶段 8：自动入库（构造库 Detail Atlas）

交付三件后**自动执行**（用户说"不入库"才跳过）：

```
python3 scripts/library_add.py --add --name 节点名 --category 部位     --tags 标签1,标签2 --spec spec.json --description "假设清单+注记对照"     --model xxx_Rhino7.3dm --ghx xxx_参数化.ghx --preview xxx_轴测.png     [--pdf 原始图纸.pdf] [--refs 参考照片目录]
```

- 编号 NNN_名称 按时间顺序自动分配，同名自动加 _01/_02 后缀；
- category 限 11 部位：基础/结构/屋顶/楼地面/墙面/幕墙/楼梯/景观/照明/机电/室内；
- 脚本上传全部文件到 OSS 并重建 library.js，用户刷新入口网页即见；
- 配置与节点库在 `/mnt/agents/output/构造库/`（library_oss.json + library_db.json，
  跨会话持久，勿删）。

**首次使用必须先建库**：library_oss.json 不存在 → 引导用户在阿里云控制台做两件事
（①建 OSS 桶；②建仅限此桶的专用 AccessKey），其余配置脚本自动完成：

```
python3 scripts/library_add.py --init --bucket 桶名 --region oss-cn-xxx     --ak ID --sk SECRET --password 页面密码
```

产出入口文件 `DetailAtlas_构造库_入口.html` 交付用户（下载一次，永久使用）。

## 阶段 9：排障回路

用户反馈报错 → 要报错原文（红色气泡/Event Log 截图）→ 对照
`references/ghx-format.md` 第 7 节报错表 → 二分定位（仅滑块版是否报错）。

## 附录：图纸置信度分级

| 输入 | 置信度 | 策略 |
|---|---|---|
| 矢量 PDF，标注齐全 | 高 | 正常流程，矛盾点照常问 |
| 扫描件 / 照片拍图 | 中 | 尺寸全部列入疑问清单确认 |
| 无标注示意 + 现场照片 | 低 | 关键尺寸全问；几何按模数假设并醒目标注 |

## 附录：原生电池路线（用户明确要求"可自己改逻辑"时）

默认走 C# 脚本路线。若用户强调要在 GH 内手工维护/教学用途，可改用原生电池链
（数学/盒体/移动电池搭建），简单几何（约 50 个电池以内）可行；代价是**离线无法
编译验证**，交付风险升高，须向用户说明，且排障支持更弱。

## 附录：MCP 实时控制路线（替代方案）

用户若想"AI 直接操作我电脑上的 Rhino"而非交付文件：Rhino 7 可装 grasshopper-mcp /
rhino-mcp 插件 + 本机 MCP 客户端（如 Kimi Code CLI，支持在 `~/.kimi/config.toml` 配置
MCP 服务器）。本 skill 的文件交付路线与之不冲突，且在任何环境可用。
